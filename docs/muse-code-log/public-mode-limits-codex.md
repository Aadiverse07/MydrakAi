## Existing semantics found (C2)

- `global_spend_cap_usd` is not daily or per process: the runner uses it to
  bound cumulative estimated reservations in the persistent shared ledger.
  The ledger has no time reset. Replacing/deleting the ledger would start a new
  local record; no provider-side billing cap is established.
- Daily counters use `datetime.now(timezone.utc)` and a UTC ISO calendar-date
  key. A new date naturally begins at UTC midnight; prior rows are retained.
- Only `_photo()` invokes `PublicLimitStore.reserve_photo()`. Voice updates are
  currently normalized as `kind="other"`, and the runner has no voice path;
  they do not count. Text and command updates likewise do not use these limits.

## Photo privacy gate review (C5)

No gate was changed. `run_telegram_bot.py` constructs `OfflineTelegramAdapter()`
without `data_policy_value` or evidence. In `src/mydrak/bot/adapter.py`,
`_photo()` parses missing policy as private, detects missing evidence, and
returns `blocked` before external processing. In
`src/mydrak/telegram/runner.py::_photo()`, continuation also requires
`spark_config["allow_private_upload"] is True`, verified rights, verified
STANDARD provider mode, and evidence. Current config does not opt in, and the
runner's default adapter cannot pass the earlier policy/evidence gate. Any
future change requires owner decisions about consent/privacy notice and an
approved evidence source plus an explicit private-upload config review.
